Notes for comparison.csv
============================================================

AUPRG / AP_norm are baseline-anchored skill scores (random -> 0 at any
prevalence), NOT prevalence-invariant; AUROC is the only invariant column.
[1] AUPR is the vendored benchmark's trapezoidal auc(recall, precision)
    (the auc(recall, precision) call in cal_metrics), kept for comparability with
    published SLMGAE/SLGNN/NSF4SL tables. It linearly interpolates between
    PR points, which no classifier achieves, and rewards ties: a CONSTANT
    score matrix scores exactly (1+baseline)/2 — i.e. the `baseline`
    column of this very table determines it, and it can exceed real
    models' AUPR. compare.py prints the value under each CV's table; no
    number is quoted here: an earlier footnote quoted 0.5786, the value
    under the pre-2026-08-10 fold set, which went stale when the label
    rule changed.
    Report AP (average precision), which gives a constant predictor exactly
    `baseline`.
[2] maxF1 is the MAXIMUM F1 over the PR curve, i.e. an oracle threshold
    chosen against the test labels (the max-F1 expression in cal_metrics).
    It is applied identically to every model, but it is not an operating
    point any deployed model could pick.

All models rank against the SAME shared gene universe
(sl_comparison/folds/genes.txt) on the SAME folds, siamese_sl included
(every siamese config.json carries folds_dir=../sl_comparison/folds).
The columns differ only in how they are NORMALISED:
  R@k       hits@k / #relevant. Correct as published - prefer these.
  NDCG@k    vendored: IDCG taken over the model's OWN top-100, so IDCG =
            min(k, hits-in-top-100) instead of min(k, #relevant)
            (cal_metrics' ndcg_score call, handed y_bool over the model's
            own top-100). Inflated.
  NDCG@kc   same ranking, IDCG from the true #relevant. Corrected.
  MAP@k     vendored: AP divided by hits-in-top-k rather than
            min(k, #relevant) (calculate_AP_at_k). Inflated more
            than NDCG.
  MAP@kc    same ranking, divided by min(k, #relevant). Corrected.
  P@10      vendored: hits/min(k, #relevant) - a second copy of R@k
            whenever #relevant <= k (cal_metrics' precision_k block),
            not precision.
  P@10t     true hits/k.
The corrections usually lower scores and lower the WEAKEST retriever
most, but not always: NDCG@kc can EXCEED NDCG@k on a row with many tied
scores (sklearn's ndcg_score averages tied gains; the corrected DCG is
positional). On the 2026-08-06 run they reordered no cell. See
retrieval_metrics.py.
degen-rows = fraction of scored test genes whose score row is CONSTANT.
  Those genes' @k values are an arbitrary tie-break, not model output, and
  do not reproduce across numpy versions. Any row with a non-trivial
  degen-rows figure has a retrieval column that should not be published.

aupr_norm is derived from `aupr` and inherits its defect: it is
(aupr - baseline) / (1 - baseline), so a constant predictor scores
0.5 rather than 0. Use ap_norm. Both are in this CSV for archival
completeness; only ap / ap_norm / auprg / auroc are safe to report.


PARAMETER COUNTS (the number in each model's label)
  Counted identically for all rows by model_params.count_parameters: every
  torch parameter with requires_grad=True at model-construction time.
  Caveats a reader will otherwise draw the wrong conclusion from:
   - SLMGAE's count is dominated by a (3, n_genes, n_genes) attention block
     (234,649,008 of 253,547,952 = 92.6%). Gradient reaches it only at
     training-edge positions, so ~96% of the total never updates; its
     effective trained size is ~10.7M, not 253.5M.
   - siamese_sl's count EXCLUDES its frozen input feature matrix (n_genes x k,
     the pretrained embeddings after the PCA arm's PCA), which is an input,
     not a parameter. k is the encoder's input width: in PCA arm none (no
     PCA) the concatenated width of the selected modalities, which moves with
     the selection (4,424-4,864 on the sets selected so far, i.e. ~86-94M
     values at n_genes = 19,397); in arms joint, per_modality and both the
     width the PCA keeps, which a variance target resolves per fold (train.py
     logs it; an exact PCA_JOINT_DIM fixes the joint PCA's). This run's k is
     fold_metrics[].input_dim in each combo's results.json.
   - A siamese_sl label reads "<n> mean of <K> folds" (k, hence the entry
     layer, differs by fold under a variance-target PCA; in arm none every
     fold has the same count): the per-fold mean, also the CSV row
     trainable_params_fold (mean, population sd). Its CSV trainable_params /
     total_params rows are the LAST fold's count only (model_params.json is
     rewritten at every fold start), as is the label of a siamese row with no
     per-fold counts. Quote the mean.
   - BilinearProbe's count is W (latent x k, k the fold's input width, as
     for siamese_sl) plus tau and b; its label is the per-fold mean, like a
     siamese_sl row's (run_probe.sh writes trainable_params_fold_*).
  DegreePrior(0) is exact: it has no parameters at all.

  SLGNN: SynLethKG kg2id.txt (SLGNN repo @ c56e23fbd20e) ships without the
    SL / SR / non-SL relations AND without every other gene-gene edge

    all 1,251 non-label triples missing from it lie on SL pairs. On the
